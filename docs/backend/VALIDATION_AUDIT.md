# Đối chiếu validation API

Tài liệu kiểm kê input và kết quả đã kiểm tra; không coi danh sách này là chứng nhận mọi nhánh đã được kiểm thử. Các endpoint bên dưới có tiền tố `/api/v1`. Backend lấy identity từ token; Data API nhận identity qua HTTP nội bộ và xác thực service key. 400 là lỗi input, 401 là thiếu/invalid token, 403 là sai quyền; các lỗi 404/409 phụ thuộc tài nguyên và trạng thái.

| Nhóm / endpoint | Input chính cần kiểm tra | Hiện trạng và bằng chứng |
|---|---|---|
| `POST /auth/login`, `/auth/google`, `/auth/register` | username/password; idToken; username, password, fullName, email, phone, role, shopName, shopTagline | Đã kiểm tra kiểu phone, shopTagline, role khi đăng ký ở hai tầng; test `test-auth-input.mjs`. Login/Google còn cần audit mọi giá trị biên và kết quả DB. |
| `GET /auth/me`, `PUT /auth/profile`, `POST /auth/change-password`, `/auth/seller-shop` | Token; fullName, email, phone, avatarUrl, address; currentPassword/newPassword; shopName | Có validation tại controller; profile/address có test MySQL riêng `test-address-mysql.mjs`, avatar có `test-avatar-mysql.mjs`. Profile cho phép sửa từng trường, giữ trường bỏ qua và chặn phone sai kiểu/định dạng; MySQL cô lập kiểm tra update từng phần và avatar. Cần rà các nhánh lỗi còn lại. |
| `POST /auth/refresh`, `/auth/logout` | refreshToken | Có kiểm tra token; test refresh/password hiện có. Chưa audit lại đầy đủ nhánh sai kiểu và hết hạn trong lần này. |
| `GET /cart`, `POST /cart/items`, `PATCH /cart/items/:itemId`, `DELETE /cart/items/:itemId`, `DELETE /cart/items`, `DELETE /cart`, `POST /cart/sync`, `PATCH /cart/selection` | variantId/productId, qty, selected, replaceQty; itemId; selectedOnly/selected; items; shopId | Chặn kiểu ID giả mảng/số không an toàn, qty và boolean sai; `test-cart-validation.mjs` mock và `test-cart-sync-mysql.mjs` trên MySQL riêng. Đã chặn itemId không đúng định dạng trên sửa/xóa; cần tiếp tục rà productId và dữ liệu biên. |
| `POST /orders/preview`, `POST /orders` | items.variantId/qty, shippingMethod, voucherCode; thêm address, paymentMethod, note và header Idempotency-Key khi tạo | Giới hạn item, số lượng, phương thức và độ dài tại Data API; sửa chặn ID bị ép kiểu khi tạo đơn. `test-checkout-preview.mjs` và `test-cart-validation.mjs` dùng mock; chưa audit toàn bộ biến thể request. Checkout lưu địa chỉ mặc định đầu tiên trong cùng transaction; MySQL cô lập kiểm tra lưu, giữ địa chỉ cũ, retry, đồng thời và rollback. |
| `GET /orders`, `POST /orders/:orderId/cancel`, `POST /orders/:orderId/confirm-received` | limit, offset, orderId | Owner lọc theo user; kiểm tra ID. Phân trang sai trả 400; cho phép `limit=0` để đọc tổng kết buyer. Cần tiếp tục kiểm tra mọi trạng thái/owner. |
| `GET /seller/shop`, `PUT /seller/shop`, `POST /seller/shop/resubmit` | name, tagline, description, province, address, logoUrl, bannerUrl | Yêu cầu seller/admin tại Backend, Data API lấy shop theo owner; `test-shop-approval-mysql.mjs` kiểm tra quyền và trạng thái, `test-cart-validation.mjs` kiểm tra một số kiểu sai với mock. Chưa audit hết mọi input. |
| `GET /seller/products`, `POST /seller/products`, `PUT/DELETE /seller/products/:productId` | limit, offset, productId; name, categoryId, description, price, originalPrice, stock, images, status, freeShipping | Validation tại `seller-product.validation.js`; `test-seller-product-validation.mjs` kiểm tra giá/tồn và `test-cart-sync-mysql.mjs` có kiểm tra dữ liệu không đổi. Đã chặn `freeShipping`/`status` sai và phân trang sai; thuộc tính minh họa theo danh mục có test MySQL owner, thay đổi danh mục, schema cũ và schema mới. |
| `GET /seller/orders`, `PATCH /seller/orders/:shopOrderId/status`, `GET /seller/images/search` | limit, offset, shopOrderId, status, q | Route yêu cầu seller/admin; truy vấn đơn theo owner, q có giới hạn 3–120 ký tự. Phân trang sai trả 400; cần tiếp tục kiểm tra trạng thái và lỗi phụ thuộc. |
| `GET /categories`, `GET /shops`, `GET /shops/:shopId`, `GET /products`, `GET /products/:productId` | limit, offset, q, mall/featured; ID/slug; bộ lọc danh mục, shop, giá, rating, discount, sort, ids | Đã kiểm tra bộ lọc, phân trang và khoảng giá cùng SKU bằng MySQL cô lập; slug shop phân biệt với ID, có test schema cũ. Cần tiếp tục kiểm tra biên và quyền các API liên quan. |
| `GET /products/:productId/reviews`, `/reviews/eligible`, `POST /products/:productId/reviews` | productId, orderItemId, rating, comment | `test-reviews-mysql.mjs`: quyền mua, delivered, sai sản phẩm, input, trùng, đồng thời và rollback ảnh trên MySQL riêng; có test schema cũ và S3 giả lập. |
| `POST /uploads/images` | dataUrl, purpose | Kiểm tra xác thực, mục đích, MIME/chữ ký, dung lượng và giải mã ảnh; review kiểm tra owner và object trước khi lưu. Chưa test storage production hoặc client. |
| `GET /vouchers/wallet`, `POST /vouchers/wallet` | page; code | `test-voucher-wallet-mysql.mjs`: owner, input, lưu đồng thời, trạng thái và phân trang trên MySQL riêng; checkout kiểm tra điều kiện lại. |
| `POST /shipping/calculate`, `PATCH /seller/orders/:shopOrderId/tracking`, `GET /orders/:orderId/tracking` | subtotal; shopOrderId, trackingCode, carrier, autoAdvanceStatus; orderId | Kiểm tra kiểu, chiều dài và boolean; ghi mốc cùng transaction. `test-postsales-mysql.mjs` kiểm tra quyền, rollback và thiếu bảng trên MySQL riêng; chưa tích hợp hãng vận chuyển. |
| `POST/GET /orders/:orderId/returns`, `GET /seller/returns`, `PATCH /seller/returns/:returnId/status` | shopOrderId, reason, detail, images, refundAmount; status, limit, offset; sellerNote | Kiểm tra nội dung, kiểu mã đơn con và chuyển trạng thái; `test-return-status-mysql.mjs` kiểm tra owner, đồng thời và lỗi 503 khi thiếu bảng. Phân trang và trạng thái theo nghiệp vụ vẫn cần kiểm tra tiếp; `completed` không chứng minh tiền đã hoàn. |
| `GET/POST /chat/conversations`, `GET/POST /chat/conversations/:id/messages` | shopId; id, limit, offset, message, attachments | Kiểm tra ID shop, giới hạn tin và attachments ở hai tầng; test MySQL kiểm tra quyền và thiếu bảng. Chưa định nghĩa contract chi tiết cho từng loại attachment. |
| `POST /reports`, các route `/admin/...` | targetType, targetId, reason, details, evidenceUrl; resource, id, status, approvalStatus, approvalVersion, rejectionReason, enabled | Backend yêu cầu đăng nhập/admin tùy route; Data API kiểm tra nhiều enum và chiều dài. Cần kiểm thử biên, quyền và trạng thái riêng cho từng resource. |
| `POST /ai/chat`, `GET /ai/brain/profile`, `POST /ai/brain/feedback`, `DELETE /ai/brain/reset` | message, context, history; action, query, productId, helpful; x-session-id | Hồ sơ/feedback/reset yêu cầu token; chat nhận token tùy chọn, phiên khách tạm và không lấy danh tính từ client. Đã kiểm tra giới hạn input và cách ly phiên bằng mock; dữ liệu vận đơn minh họa được gắn nhãn. |

Bảng ghi các điểm đã đọc và test cụ thể; chưa chứng minh mọi trường, nhánh quyền hoặc tình huống lỗi đều đã được kiểm chứng. Ưu tiên rà tiếp các mục còn nêu hạn chế, nhất là dữ liệu đính kèm và các nhánh quyền còn thiếu. Thay đổi contract phải đối chiếu client trước.

Các mã đơn con trả hàng và đối tượng báo cáo không chấp nhận mảng hoặc số không an toàn; query filter sản phẩm/shop công khai không ép mảng thành chuỗi. Các kiểm tra mới dùng mock, không coi đây là audit đầy đủ mọi input.
