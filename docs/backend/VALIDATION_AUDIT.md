# Đối chiếu validation API

Tài liệu kiểm kê input và kết quả đã kiểm tra; không coi danh sách này là chứng nhận mọi nhánh đã được kiểm thử. Các endpoint bên dưới có tiền tố `/api/v1`. Backend lấy identity từ token; Data API nhận identity qua HTTP nội bộ và xác thực service key. 400 là lỗi input, 401 là thiếu/invalid token, 403 là sai quyền; các lỗi 404/409 phụ thuộc tài nguyên và trạng thái.

| Nhóm / endpoint | Input chính cần kiểm tra | Hiện trạng và bằng chứng |
|---|---|---|
| `POST /auth/login`, `/auth/google`, `/auth/register` | username/password; idToken; username, password, fullName, email, phone, role, shopName, shopTagline | Đã kiểm tra kiểu phone, shopTagline, role khi đăng ký ở hai tầng; test `test-auth-input.mjs`. Login/Google còn cần audit mọi giá trị biên và kết quả DB. |
| `GET /auth/me`, `PUT /auth/profile`, `POST /auth/change-password`, `/auth/seller-shop` | Token; fullName, email, phone, avatarUrl, address; currentPassword/newPassword; shopName | Có validation tại controller; profile/address có test MySQL riêng `test-address-mysql.mjs`, avatar có `test-avatar-mysql.mjs`. Cần rà soát lại toàn bộ kiểu và nhánh lỗi của từng endpoint. |
| `POST /auth/refresh`, `/auth/logout` | refreshToken | Có kiểm tra token; test refresh/password hiện có. Chưa audit lại đầy đủ nhánh sai kiểu và hết hạn trong lần này. |
| `GET /cart`, `POST /cart/items`, `PATCH /cart/items/:itemId`, `DELETE /cart/items/:itemId`, `DELETE /cart/items`, `DELETE /cart`, `POST /cart/sync`, `PATCH /cart/selection` | variantId/productId, qty, selected, replaceQty; itemId; selectedOnly/selected; items; shopId | Chặn kiểu ID giả mảng/số không an toàn, qty và boolean sai; `test-cart-validation.mjs` mock và `test-cart-sync-mysql.mjs` trên MySQL riêng. Cần tiếp tục rà itemId, productId và dữ liệu biên của từng route. |
| `POST /orders/preview`, `POST /orders` | items.variantId/qty, shippingMethod, voucherCode; thêm address, paymentMethod, note và header Idempotency-Key khi tạo | Giới hạn item, số lượng, phương thức và độ dài tại Data API; sửa chặn ID bị ép kiểu khi tạo đơn. `test-checkout-preview.mjs` và `test-cart-validation.mjs` dùng mock; chưa audit toàn bộ biến thể request. |
| `GET /orders`, `POST /orders/:orderId/cancel`, `POST /orders/:orderId/confirm-received` | limit, offset, orderId | Owner lọc theo user; kiểm tra ID. Phân trang hiện dùng giá trị mặc định khi input không hợp lệ; cần thống nhất contract trước khi đổi sang 400 và kiểm thử các trạng thái/owner. |
| `GET /seller/shop`, `PUT /seller/shop`, `POST /seller/shop/resubmit` | name, tagline, description, province, address, logoUrl, bannerUrl | Yêu cầu seller/admin tại Backend, Data API lấy shop theo owner; `test-shop-approval-mysql.mjs` kiểm tra quyền và trạng thái, `test-cart-validation.mjs` kiểm tra một số kiểu sai với mock. Chưa audit hết mọi input. |
| `GET /seller/products`, `POST /seller/products`, `PUT/DELETE /seller/products/:productId` | limit, offset, productId; name, categoryId, description, price, originalPrice, stock, images, status, freeShipping | Validation tại `seller-product.validation.js`; `test-seller-product-validation.mjs` kiểm tra giá/tồn và `test-cart-sync-mysql.mjs` có kiểm tra dữ liệu không đổi. Phân trang sai hiện được mặc định; `freeShipping` cần audit kiểu và hành vi. |
| `GET /seller/orders`, `PATCH /seller/orders/:shopOrderId/status`, `GET /seller/images/search` | limit, offset, shopOrderId, status, q | Route yêu cầu seller/admin; truy vấn đơn theo owner, q có giới hạn 3–120 ký tự. Cần kiểm tra biên phân trang, trạng thái và lỗi phụ thuộc. |

Các nhóm sản phẩm công khai, shop công khai, upload, admin, vận chuyển, trả hàng, chat, AI và ví voucher chưa được audit đầy đủ trong tài liệu này. Cần lập bảng chi tiết và kiểm thử riêng trước khi kết luận validation toàn hệ thống. Thay đổi contract phân trang hoặc schema phải đánh giá client trước.
